# ION-ONIX manual configuration

## Introduction

This document explains the various environments/networks that ION supports and the ONIX configuration that needs to be done. We have scripts in each of the folders (bapONIX, bppONIX, catalogPublisher and testnet) that help configure ONIX. This document explains only the bare minimum configuration required using the Simple Key Manager as the key managing option. For more extensive discussion on the configuration, refer to the [document here](https://github.com/beckn/beckn-onix/blob/main/CONFIG.md). This document lists the behavior of the scripts if someone wants to do it manually. When there are two source of config information (script and this document), there is a risk that they go out of sync. It is a risk this document faces.

ION has currently three networks (environments). The following are the NETWORK_ID values and the purpose of the network. 
1. `ion.id/testnet` - This is used by docker compose environments that users use to try things out. 
2. `ion.id/staging` - This is used by NPs when they are ready to test their software against other NPs
3. `ion.id/prod` - This is the production environment for live, actual transactions.

## Notes on values
1. `SUBSCRIBER_ID` - This will the subscriberId registered either in dedi.global or self published by NP e.g. `dc-bap.ion.id`
2. `PRIVATE_KEY` - This is private key of the keypair that is generated for this instance of ONIX e.g. `THNHFIGWN8IutTzeWWNPCgSeDIfZjv/C80AoRClSMc8=`
3. `PUBLIC_KEY` - This is public key of the keypair that is generated for this instance of ONIX e.g. `jnSciDWwaDwcvzxMuacsOEvO7g/6TdD/cf4OJrwCZjA=`
4. `KEY_ID` - This is the ID of the subscriber record on DeDi. It can either be the recordId field auto generated by Dedi (e.g. `76EU7JHvbQGBL8UnkKpKK32MMnCbnjjkPftuCcBJ7DULsxVq53NJRz`) or the record-name field of the record (e.g. `dc-bap`)
5. `NETWORK_ID` - This is the path to the registry of the network mentioned above e.g. one of (`ion.id/testnet`, `ion.id/staging`, `ion.id/prod`)
6. `CATALOG_BASE_URL` - This is the path of the catalog index file where the BPP is publishing its catalog. It is the same as in the metadata of the BPP subscriber record. e.g. `https://my-bpp-site.com/beckn/catalog/becknCatalogs.index.json`

## Configuration required for ION Observability

To enable ION Observability, you need to do the following 
1. See the bapONIX or bppONIX folders for sample configurations
2. Create a container from the `otel/opentelemetry-collector-contrib:latest` image.
3. Create a config file say in the otel-collector-bap folder under config. Set the network collector endpoint to the ION network collector endpoint (currently `https://netcol.staging.ion.id` for both the BAP and the BPP)
4. Configure otelsetup plugin in the BAP/BPP config file with config similar to the one below
5. The fields that need to be sent are configured in the audit-fields.yaml file. 

```
plugins:
  otelsetup:
    id: otelsetup
    config:
      serviceName: "beckn-onix"
      otlpEndpoint: "otel-collector-bap:4317"
      enableMetrics: "false"
      enableTracing: "false"
      enableLogs: "true"
      timeInterval: "5"
      auditFieldsConfig: "/app/config/audit-fields.yaml" # this can be git url
      producer: "{{SUBSCRIBER_ID}}"
      producerType: "bap"
```
